## 从上一章那个 TOOLS 字典说起

第 3 章结尾，`loop/agent.py` 里有这么两行：

```python
TOOLS = {
    "get_time": get_time,
    "get_weather": get_weather,
}
```

两个工具，一个字典，跑得很好。

现在你想加第三个工具，让它能读文件。把 `read_file` 写进去，很顺。再加一个搜关键字的 `search_keyword`，也还行。加到第五个、第六个，问题就来了：

- **工具描述是随手写的**：`get_weather` 的 description 是临时敲的。该调用的时候，模型想不起来；不该调用的时候，它又抢着用。
- **一次参数错误，程序就退出**：模型把 `city` 写成 `cities`，代码去取 `args["city"]`，抛出 `KeyError`。第 3 章的 `get_weather` 就埋着这颗雷，工具一多，这个错误就会碰上。
- **主循环越来越乱**：为了让模型能读文件，你要在循环里加判断、加 `try`、加路径检查。但循环是 Harness 的心脏，它只该做一件事：调用工具、看结果、再决定下一步。检查和报错应该放进工具自己里面。
- **权限没处写**：第 3 章的工具都是只读，所以「做之前要不要问人」可以先空着。现在要加 `fs_write`、`apply_patch`，它们会 **直接改你的文件**。「做之前要不要问人」得有个固定的地方写下来。

四个症状指向同一个病因：**`TOOLS` 字典里只有名字和函数，缺说明、参数格式和权限。**

从这一章起，我们进入 **阶段二（L1 个人自用）**。Harnex 要开始真的替你干活：读文件、改代码、搜仓库。这些活需要十个、二十个工具，所以先得有一套能装下十个、二十几个工具的 **工具系统**。

> **工具是插头，注册表是插排，权限声明是插头上印的额定功率。** 每个工具按同一套格式来写，注册表才收得下。格式里写明它能做什么、会不会改文件。对不上的，就不让它注册。
