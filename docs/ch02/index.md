## 从上一章最后那个实验说起

第 1 章结尾，你把同一句话用两种说法各问了一遍：

```text
【说法 A】杭州有什么值得去的？

【说法 B】你是一位在杭州生活了十年的本地向导。
        我要带一位 65 岁的长辈去杭州玩三天，他腿脚不便，不喜欢人多的地方。
        请推荐行程，要求：每天最多两个景点 / 必须给出午饭晚饭建议 /
        按「上午、午饭、下午、晚饭」四行输出 / 不确定的信息直接说不确定，不要编。
```

结果是，说法 B 明显更具体、更好用，也更少编造。

这一章就要回答一个问题：**那几个字改在了哪里，为什么会有这么大差别？**

按这个顺序讲。先看接话的模型是什么、它为什么会这样反应（2.1），再拆说法 A 和说法 B 差在哪几个字（2.2）。

1. **LLM** —— 接话的是个什么东西，它天生有怎样的脾气
2. **Prompt** —— 你怎么跟模型说话，说法 A 和说法 B 的差距在哪

这两件事看起来是两门手艺，本质却是一句话：**话是你写的，脾气是它自带的。** 你要学的不是「讨好」模型，而是在它的脾气范围内，把话说到点子上。

读完这一章，你要能做到四件事：

1. 用五个零件写出一条像样的 prompt，并说清它比「随口问」好在哪里
2. 看懂一次 API 调用里到底发生了什么——为什么「模型没有记忆」
3. 跑通 2.3 节的工具调用，亲眼确认 **模型只返回调用请求、不执行**
4. 知道温度、上下文窗口、token 这三个东西什么时候会咬你一口

> 这是全书唯一一次系统讲 prompt 与模型机制。后面每一章都在用这里的结论，但不再重复解释。
