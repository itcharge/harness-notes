# 小结与验收

## 本章小结

1. **模型是一个无状态函数**：`response = f(prompt)`，不保存任何东西。由此推出三条——记忆要自己实现、上下文是记忆带宽、同样输入不保证同样输出。（它常被叫「纯函数」，但严格说不是——真正的纯函数要求「同样输入必得同样输出」。）
2. **一段好 prompt 有五个零件**：角色、任务、输入、约束、输出格式。缺哪个，结果就烂在哪。
3. **你发的是一叠消息**：system 是长期规则，history 是历史，user 是本轮。「AI 记得我」的真相，是程序把历史重新塞回去。
4. **tool use 的本质是「模型点菜，你执行」**：它只输出「请调用某函数」，执行权始终在你手里。模型工具调用 = 两次 LLM 调用 + 一次你的执行。
5. **Prompt 是「说好话」的功夫，Harness 是「办成事」的工程。** 参数和技巧只能改善「说得怎么样」，解决不了「能不能办事」。

## 动手任务

1. **重写一条 prompt**：挑一条你平时常用的 prompt，用五个零件各检查一遍，把改前改后都存下来，写一句「差在哪」。
2. **跑通工具调用**：完成 2.3 节的代码，运行后打印原始返回，亲眼确认 `tool_calls` 里只有参数、没有结果。
3. **抽出 `llm.py`**：把 2.3 节的 `chat()` 落地成文件，让你的代码之后只调用它。

## 验收清单

- [ ] 能用五个零件重写一条 prompt，并说清「改前改后差在哪」
- [ ] 打印过一次完整 `messages`，能指出 system / history / user 三层各是什么
- [ ] 2.3 节的代码跑通一次带工具调用的对话，能讲清每一步的数据流
- [ ] 能说出「模型没有执行任何工具」的证据（贴出原始返回里的 `tool_calls`）
- [ ] `llm.py` 抽象完成，切换模型只需改一处

## 本章的常见误区

- **把 prompt 当许愿池**：形容词堆一屏、指令互相打架，结果还不如老老实实说清任务。
- **不做历史拼接却期待记忆**：模型每轮都是白纸，抱怨「它怎么忘了」是设计错误，不是模型的问题。
- **以为模型会自己执行工具**：等着它返回天气结果，实际它只返回了调用请求。这是 Agent 新手最容易卡住的一步。
- **工具调用场景用高温度**：参数格式随机崩坏，解析失败率飙升。
- **超长 prompt 拖慢首字**：第一次体感 TTFT 随 prompt 长度增长。
- **把敏感信息写进 prompt**：不该进上下文的东西一旦进去，就进入了日志与账单（第 15 章回收）。

## 自测题

1. Prompt、Agent、Harness 三者各解决什么问题？用一句话分别说清。
2. 一段好 prompt 有哪五个零件？「给它一个示例」属于哪一类技巧？
3. 为什么说模型是「无状态函数」？它为什么不能算真正的「纯函数」？这对 Agent 设计有哪三条推论？
4. system / history / user 三层分别相当于什么？为什么说「记忆是程序塞回去的」？
5. 模型返回了 `tool_calls`，接下来该谁做什么？这个过程中模型总共会被调用几次？
6. 上下文窗口是「桌面」还是「抽屉」？这个区别为什么重要？
7. 结构化输出能消除解析失败吗？为什么？
8. TTFT、TPOT、E2E 分别量度什么？Agent 的 E2E 主要由什么决定？

## 本章术语速查（中英对照）

| 中文    | 英文                 | 一句话解释                        |
| ----- | ------------------ | ---------------------------- |  
| 提示词   | Prompt             | 你发给模型的全部文字                   |  
| 系统提示  | System Prompt      | 长期规则：角色、底线、风格                |  
| 角色    | Role               | `system` / `user` / `assistant` / `tool` 四种消息身份 |  
| 示例学习  | Few-shot           | 给几个「输入 → 输出」的例子当模板           |  
| 思维链   | Chain of Thought   | 让它先写判断依据再给结论                 |  
| 温度    | Temperature        | 输出随机性旋钮；工具调用用 0              |  
| 上下文窗口 | Context Window     | 一次调用能看到的最大长度                 |  
| 令牌    | Token              | 计费与长度的基本单位                   |  
| 工具调用  | Tool Use           | 模型输出「请调用某函数」的请求，由你执行         |  
| 结构化输出 | Structured Output  | 让返回结果符合固定 schema             |  
| 首字时延  | TTFT               | 从发出请求到第一个 token 到达           |
