# 1.4 Harnex 与全书路线

## 1.4.1 用的人变了，要会的东西就变了

全书按五级往前走。每一级的差别，是谁在用它。

只有你自己试一次，能跑就行。要天天用，它得真的办成事。要放着跑一个月，你得知道它为什么失败、花了多少钱。要给同事和朋友用，你得想「张三能不能看到李四的数据」。要发给陌生人，你得想怎么安装、怎么扩展、怎么防止滥用，出事之后怎么追责。

用的人一换，就要补上一批新能力。后面每一章都是这样来的。

| 级别 | 使用者 | 这一级实际学会什么 | 章节 |
| --- | --- | --- | --- |
| **L0** Demo 能跑 | 自己（图个新鲜） | 第 1 章把概念说清；第 2 章完成一次工具调用；第 3 章写出循环。达标动作在第 3 章 | 第 1–3 章 |
| **L1** 个人自用 | 自己（每天都用） | 工具系统、技能包、上下文、执行、检索、规划 | 第 4–9 章 |
| **L2** 可靠可观测 | 自己（敢连续跑一个月） | 可靠性、交互、可观测与成本、评测、框架地图 | 第 10–14 章 |
| **L3** 多用户安全 | 同事与朋友 | 沙箱与审批、多用户隔离 | 第 15–16 章 |
| **L4** 分发达标 | 陌生人 | 三个实战案例、分发与插件生态、毕业设计 | 第 17–21 章 |

第 1 章先把五级看全，是为了知道后面每一章在给哪一种使用者补能力。你现在要做的，是把 L0 的概念说清。循环要到第 3 章才写出来。

**企业级** 在本书里指 L3 往上的做工：数据隔开、操作留得下记录、出事追得到人。它说的是敢交给别人长期用，和客户是公司还是个人无关。一个有上亿用户的购物 App，账号互相隔离、支付查得到来源、事故能定位到具体操作，这就是企业级，用它的是个人也一样。卖给公司的内部工具，如果谁都能看到谁的数据、删了东西没有记录，做工仍然不够。

## 1.4.2 贯穿项目叫 Harnex

1.1 节那个会查天气、会因为下雨改行程的助手，从这里起叫 **Harnex**。代码要到第 3 章才写出来，大约七十行，能自己走完多步。这一章只给它写第一份定位。

这个名字取自 **Harness + Nexus**。Harness 是把模型装进任务的那层运行系统，Nexus 是模型、工具、技能、策略接在一起的地方。

全书只跟这一个项目。它从一段脚本长成你自己每天在用、别人也能安装和部署的 Harness。规则很简单：**每章补上一项新能力。**

```text
第 3 章   循环            → 它能按结果继续走下一步
第 4 章   工具系统        → 第 3 章写死的函数，变成可注册、可扩展的工具
第 5 章   技能包          → 它会按一份方法说明做事
第 6 章   上下文与会话    → 它记得住这次对话，也能回看轨迹
第 15 章  权限与沙箱      → 它被限制在允许的范围内
第 21 章                  → 别人也能部署
```

第 7 章到第 14 章、第 16 章到第 20 章，是把这几项从「能跑」做成「敢用」。到最后一章，你手里是一个自己每天都在用、别人也能装的产品。**你的 git log，就是这本书的毕业作品。**

第一次读，按章号往下走。标了「台阶」的环境配置可以跳过。只想先得到一个自己敢用的 Harnex，读到第 14 章（L2）可以停。第 15 章以后，是使用者从自己换成别人之后才要补的能力。有经验的话，可以先看每章末尾的验收标准，再决定读哪一节。章节上的「入门 / 进阶 / 高级」说的是阅读难度。达标线看的是谁在用。

Claude Code、OpenAI Codex、Gemini CLI、DeepSeek Harness 长得不一样。把外壳拆开，运行时通常都能看见 1.2 节对齐过的四件：循环、能力注册表、会话日志、执行策略。客户端是同一套运行时的不同入口，所以很多架构图不单列它。各家值得看的设计放在本章小结的延伸阅读里。本书学它们的架构想法，用 Python 从零写一遍。亲手写过循环、上下文和审批，再去看它们的取舍，会清楚很多。

## 1.4.3 先写一份定位书

这一章要写下来的，是一份「框架定位书」，五句话以内。API 体验和选型练习在本章小结，和这份定位书是两件作业。

```text
1. 它服务谁：__________（先写你自己，再写你身边的人）
2. 它最常干的三件事：__________
3. 它需要哪几类能力：__________（查资料 / 操作文件 / 执行命令 / 其他）
4. 它明确不做什么：__________（这一条最重要，至少写三条）
5. 它的第一条红线：__________（比如「删除文件前必须先问我」）
```

这是初版，记作 **v0.1**，和后面 Harnex 代码的版本号对齐。第 3 章写出第一版代码后，会把它更新到 v0.3，补上哪些已经能做、哪些还没做。后面每加一项功能，都回来对一次：这件事在定位书里吗？不在，就先不做。

如果 Harnex 就是那个安排出行的助手，第 2 条可以写成「查天气、比较交通、起草行程」，第 4 条写上「不付款、不改别人的日历、不编造闭馆信息」。第 4 条写具体，至少三条。比如：不替用户付款，不在询问之前删除文件，不回答定位书范围之外的任务。定位书写的是边界。范围先写窄，确认自己真的会用，再加下一件事。
