# 小结与验收

## 本章小结

1. **纯 Chatbot 负责生成回复，Workflow 的路径是人事先定的，传统 RPA 按预设脚本操作界面。** 三者的下一步都不是模型在运行中选定、再根据结果继续调整的。
2. **本书所说的 Agent，是 LLM 在运行时选择动作、观察结果，并通过受控循环推进任务。** 脑子、手、循环，缺一块就会退回更简单的形态。调一次工具，在本书里还只是 LLM 应用。
3. **Harness 是模型权重之外的运行系统，模型是发动机。** 产品架构有五个部件：循环、能力层、上下文与会话、权限与沙箱、客户端。第 3 章还会讲循环内部的五个部件，那是另一张清单。
4. **能力分两层**：工具负责动作，可以是本地函数、远程 API 或 MCP 服务；技能包负责方法。技能包可以渐进加载，未命中的正文不必占满这一次的上下文。
5. **能用确定性代码写清楚的事，先不要用 Agent。** 按 1.3 节的四句顺序选型；要花钱、要删除、要对外发送时，把旋钮拧回半自主。

本章定下的四个词，后面每一章都在用：

| 概念          | 一句话定义                             |
| ----------- | --------------------------------- |
| **Prompt**  | 你发给模型的全部文字（第 2 章展开）               |
| **Agent**   | LLM 在受控循环中选择动作、观察结果、继续推进          |
| **Harness** | 模型权重之外、把 LLM 组织成可运行 Agent 的那层系统   |
| **企业级**     | L3 起的工程质量：敢交给别人长期用，与客户是 B 还是 C 无关 |

## 动手实践：看一次「它只会接话」

下面三次实验是体验，不是本章的项目交付物。本章真正要交的，是 1.4.3 节那份五句话的定位书。

要跑通调用，需要三样东西：Python、`openai` 包、一个 API Key。DeepSeek 和通义千问都兼容这套 SDK，差别只在三处：Key 放进哪个环境变量、`base_url` 指向哪家、`model` 写成哪个名字。

> 这里只对话、不调工具，是为了让你看见：它能接出下一段内容，但不能自己去办事。这个体感是第 3 章的起点。

**实验一：看清它到底返回了什么**

下面以 DeepSeek 为例。这一次只看整段回复。账号里的模型名不同，就换成你能调用的那个，观察的对象不变。

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["DEEPSEEK_API_KEY"],
    base_url="https://api.deepseek.com",
)

resp = client.chat.completions.create(
    model="deepseek-flash",
    messages=[{"role": "user", "content": "杭州有什么值得去的？"}],
)
print(resp.choices[0].message)
```

换成通义千问时，只改这三处。`{WorkspaceId}` 换成你的工作空间 ID：

```text
api_key=os.environ["DASHSCOPE_API_KEY"]
base_url="https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1"
model="qwen3.8-max"
```

请仔细看输出：它返回的是一段内容，外加一个 `role` 字段。消息体里还有 `content`。

没有天气，没有订单，也没有真的执行过任何操作。所谓「AI 回答了」，在这一次调用里就是「它生成了下一段内容」。

**实验二：改几个字，看结果差多少**

同一件事，用两种说法各问一次。`【】` 只是给你区分的标记，发出去之前删掉：

```text
【说法 A —— 随口问】
杭州有什么值得去的？

【说法 B —— 给出角色、任务、输入、约束和输出格式】
你是一位在杭州生活了十年的本地向导。
我要带一位 65 岁的长辈去杭州玩三天，他腿脚不便，不喜欢人多的地方。
请推荐行程，要求：
1. 每天最多两个景点，避开需要长时间步行的路线；
2. 必须包含午饭和晚饭的具体建议；
3. 按「上午 / 午饭 / 下午 / 晚饭」四行输出，每天一段；
4. 不确定的信息（比如某个景点是否还在维修）请直接说不确定，不要编。
```

对比结果：说法 B 通常更具体、更可执行，也更少编造。

说法 B 里已经放着第 2 章要拆开的五个零件：角色、任务、输入、约束、输出格式。下一章给它们名字，并说明为什么改几个字会差这么多。

**实验三：把角色放进 system**

把实验一的 `messages` 改成两层再跑一次。第一层用说法 B 的角色和「不要编」；其余要求放进 user。结构如下：

```text
{"role": "system", "content": "你是一位在杭州生活了十年的本地向导。不确定的信息直接说不确定，不要编。"}
{"role": "user", "content": "我要带一位 65 岁的长辈去杭州玩三天，他腿脚不便，不喜欢人多的地方。请按上午、午饭、下午、晚饭推荐行程。"}
```

这是你写的第一段 system prompt。它为什么要和 user 分开，第 2 章解释。保存三次输出，方便对照。

## 本章的常见误区

- **什么都用 Agent**：规则能写成确定代码的场景硬塞给 LLM，又贵又不稳定。先走 1.3 的第 1 句。
- **一开始就追求全自主**：跳过「关键动作问人」，等它真的误删了东西就没有补救余地。
- **把 harness 当成「调 API」**：以为会调 LLM 就会写 Agent——漏掉的正是能力层、会话管理与执行策略。
- **把各类 AI 助手当成同一种东西**：分不清 Chatbot、Workflow、RPA、Agent，选型从第一步就错了。
- **以为模型会自己动手**：它生成的是内容或动作请求，执行的那只手是运行系统提供的。第 3 章会亲手验证这一点。

## 自测题

1. 按本书的定义，一个系统要同时满足哪两件事，才叫 Agent？
2. Agent 三要素分别是什么？缺了动作、缺了运行时判断、缺了循环，会各自接近哪一类系统？
3. 同一个模型为什么能变成差别很大的产品？模型的能力上限和 harness 各起什么作用？
4. Harness 五部件都在模型权重之外。这是否等于换模型不用改代码？它和第 3 章循环内部的五个部件是不是同一张清单？
5. 「每收到邮件就按固定类别归档打标签」该停在 1.3 的哪一句？什么情况下才升级成 Agent？
6. 「企业级」和「ToB」是不是一回事？举一个面向个人用户、但达到企业级工程质量的系统。
7. 工具和技能包分别解决什么问题？工具一定要走 MCP 吗？

## 本章术语速查（中英对照）

看到不认识的词，回这张表查：

| 中文  | 英文            | 一句话解释                           |
| --- | ------------- | ------------------------------- |
| 提示词 | Prompt        | 你发给模型的全部文字（第 2 章详解）             |
| 上下文 | Context       | 这一次调用模型能看见的全部输入                 |
| 模型  | LLM           | 生成内容或动作请求；外部动作由运行系统执行           |
| 工具  | Tool          | 模型能请求的外部动作：本地函数、远程 API 或 MCP 服务 |
| 技能包 | Skill         | 写给模型读的方法说明（通常是一份 SKILL.md）      |
| 循环  | Agent Loop    | 想 → 做 → 看 → 再想，直到完成或被熔断         |
| 外壳  | Harness       | 模型权重之外的运行系统：循环、能力层、会话、权限与沙箱、客户端 |
| 幻觉  | Hallucination | 一本正经地编造                         |
| 令牌  | Token         | 计费与长度的基本单位（第 2 章）               |
