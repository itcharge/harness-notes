# 1.1 三类常见方案与 Agent 的边界

回到章首那句：

> 帮我安排一下周末去杭州旅游行程。

这句话真正要的，不是一份景点清单，而是查天气、比车次、选酒店、排日程，最后交出一张能照着走的行程表。

过去让机器参与这件事，常见的是三类做法。它们今天仍然并存，各自解决一部分问题，也各自有明确的失效点。

## 1.1.1 三类常见方案

**Chatbot（聊天机器人）：会说，默认不直接做事。**

你问什么它答什么，措辞得体、知识面广。纯 Chatbot 的全部能力是生成回复：它不会自己去查天气、订票，也不会把结果写进你的日程。窗口里看起来「记得你刚才说的话」，通常是外壳把先前的对话再次送了进去，不是模型自己留着一份记忆。记忆怎么保存，是第 6 章的事。

典型场景：答疑、润色文稿、解释概念。  
失效点：任何需要「真的去做」的环节。它给你建议，执行仍然归你。

**Workflow（工作流）：路径是人定的，所以稳定。**

这次真的能干活。人先把「周末去杭州」拆成固定步骤，程序按这个顺序跑。模型可以在某一步里读文字或做判断，但下一步走哪条线，是设计时写好的。

```text
读出发要求  →  查周末天气  →  选定景点与车次  →  写入行程表
```

它快、稳、便宜、可预测。今天企业里大量的自动化都属于这一类。规则简单、在一个程序里就能算完的，甚至不必上工作流，一段普通程序更直接。

失效点：流程之外的分支。如果周末临时改成工作日，或者同行的老人不能久走，而这两条线都没有被事先写好，它不能自己改道，只能卡住或交给人。

**RPA（机器人流程自动化）：按预设脚本操作界面。**

传统 RPA 录下人操作电脑的过程，然后反复重放：点这个按钮、填那个框、按下回车、切到下一个系统。它擅长那些只能通过老旧界面才够得着的操作，比如往一个二十年前的系统里录数据。

失效点：界面一变就断。按钮挪位、弹出验证码、页面慢两秒，脚本并不理解自己在办什么业务。现在也有把模型接进界面操作的产品，那是第 19 章的事。这里说的 RPA，指运行时不再重新判断的那一类。

## 1.1.2 先问一句，再看完整定义

三者对照：

| 做法 | 擅长 | 失效点 | 一句话定位 |
| --- | --- | --- | --- |
| Chatbot | 对话、答疑、生成文本 | 默认不执行外部动作 | 会说，办事仍归你 |
| Workflow | 固定流程、大批量、路径已知 | 没写进流程的分支 | 稳定，路径是人定的 |
| RPA | 操作老旧界面、机械重复 | 界面一变就断 | 会按脚本操作界面 |

这三类常被统称成「AI 助手」。要分开它们，先看运行时下一步由谁决定：

> **运行的时候，下一步是谁定的？**

- 纯 Chatbot：等你说出下一句，它才回复。
- Workflow：人提前写好路径，程序按路径走。
- 传统 RPA：人提前录好操作，程序按录像重放。

三者的下一步都是人事先定好的，不是模型在运行时选的。

只问这一句，还定不了什么是 Agent。模型也可以听你一句、选一个工具、回答一句。那也是模型在选下一步，但只选一次，选完就停。

规则能一条条写清楚时，上面三类更便宜，也更稳定。具体怎么判断，放在 1.3 节。

## 1.1.3 脑子、手、受控循环

同样这件事，交给本书所说的 Agent，过程是这样。

```text
你：    帮我安排一下周末去杭州旅游行程

助手（想）：先看天气 → 再查车次 → 再看酒店 → 最后写成行程
助手（做）：调用 get_weather(杭州)
助手（看）：返回"周末多雨，18~24℃"
助手（再想）：下雨 → 室内行程为主，提醒带伞
助手（做）：调用 search_trains(上海 → 杭州)
助手（看）：返回三趟候选车次
……（循环，直到它认为办完了）

助手：    这是你的 3 天行程，附天气提醒和交通建议
```

请留意一件事：**「先查天气、再查车次、最后写成行程」这个顺序，没有人逐条告诉过它。** 发现下雨后调整推荐方向，也是它看到结果之后自己判断的。

这就是本书的定义：

> **LLM Agent 是这样一个系统：LLM 在运行时选择动作，观察结果，再通过受控循环继续推进，直到任务完成或被叫停。**

拆开看，只有三个要素：

| 要素 | 职责 | 本书章节 |
| --- | --- | --- |
| **脑子** | 判断、决策、选择下一步 | 第 2、3 章 |
| **手** | 真的去查、去改、去执行 | 第 3 章先用两个写死的函数，第 4 章做成可扩展的工具系统 |
| **循环** | 做完一步看结果，再决定下一步；够了就停，失控就熔断 | 第 3 章 |

缺了其中一块，它会退回更简单的做法：

- 只会生成、不能发起外部动作 → 接近纯 Chatbot
- 步骤和分支都由人事先规定 → Workflow
- 操作步骤事先录好、执行时不再判断 → 接近传统 RPA

**受控循环是分水岭。** 没有循环，一次工具调用就结束了；有了循环，它才能做一步、看结果、再调整，处理那些事先无法完全规划的任务。循环还必须有停的办法：模型自己认为办完了要能退出，绕圈不停时要能被熔断。第 3 章会把这两件事都写出来，代码大约 75 行。复杂度远比「Agent」这个词给人的印象低，真正难的是让它可靠。

## 1.1.4 单轮工具调用还不是 Agent

第 2 章先写「问一句、调一次工具、答一句」，本书把它叫 LLM 应用。第 3 章才给它装上循环。

**自主性不是免费的。** 它会判断错，会在两个工具之间来回调用，也会在你没注意时花掉一笔 token 费用。这些代价在 1.3 节展开。后面那些看着「很工程」的内容——熔断、审批、评测、日志、沙箱——都是在把这三份代价变成可控的东西。
