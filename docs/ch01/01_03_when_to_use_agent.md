# 1.3 什么时候该用 Agent

## 1.3.1 自主性有三份账单

1.1 节末尾说过：自主性不是免费的。Agent 会自己判断、自己发起动作，听上去什么都能交给它。但是每多一份自己做主，就要多付出三样成本。

- **钱**：每决定一步，就要调用一次模型。每一次模型调用，涉及到一次 token 消耗。一个任务通常三五次，绕起圈来会到十几次。
- **时间**：这些调用大多得一个接一个等。固定程序一次函数调用就结束的事，这里要走好几轮。
- **确定性**：同样的输入，不保证同样的输出。所以后面才需要评测。

看个具体的例子。把「计算个人所得税」做成 Agent，你可能得到一个算错的数，再附上一笔账单和几秒等待。它本来是一小段确定性的程序：根据输入条件参数马上算完，结果确定，调用成本几乎为零。税率每年调整，就把当年的税率表做成配置。规则会变，仍然适合「程序 + 数据」，不必改成让模型现算。

所以自主性不是越高越好。它是一个可以调的旋钮：

```text
固定流程（人定死） → 半自主（关键动作问人） → 全自主（自己决定一切）
```

成熟的生产系统大多停在中间：让模型做准备和起草，到了「要花钱、要删数据、要发给客户」再停下来问一句。第 11 章会先让它停下来问，第 15 章把这套问答写成审批档位。

## 1.3.2 按顺序问四句

遇到一个需求，按下面四句往下问。前一句已经有了去处，就停在那里。

| 顺序 | 问自己 | 答案是「是」 | 答案是「否」 |
| --- | --- | --- | --- |
| 1 | 能否用确定性代码可靠完成？ | 写普通程序。规则会变，就做成配置 | 问第 2 句 |
| 2 | 是否主要是跨系统、路径事先定好的编排？ | 用 Workflow | 问第 3 句 |
| 3 | 是否需要理解非结构化输入，并在运行中选择下一步？ | 考虑 Agent | 先不要自动化 |
| 4 | 出错是否不可逆，或代价高到不能接受？ | 加上人工审批；承担不起就不用 Agent | 可以在写明的边界内让它自己做 |

第 1 句和第 2 句都是人把路径提前定好，差别在事情跨不跨系统。规则简单、在一个程序里就能算完，写普通程序。要跨邮件、表格、工单，按固定顺序搬运，用 Workflow。

第 3 句才轮到 Agent。它适合规则写不全、输入又不是整齐表格的任务：读一封说不清的邮件，在几个工具之间自己挑下一步，或者按刚看到的结果改计划。分支一多，全写进 if-else 会膨胀，而每一步又要先看上一步的结果，也是同样的情况。

> **能用确定性代码写清楚的事，先不要用 Agent。**
>
> Agent 用在路径写不全、又必须在运行中选择下一步的时候。先问自己：这件事的规则，我能不能写成会停、会给出确定结果的代码？

还有些事适合先放着，不自动化。一次性的琐事、做完对不上的判断、做错了撤不回来的操作，都先留在人手里。交给 Agent 之前，你得能核对结果：行程可以自己看一遍，税款必须和税率表对得上，删除必须能从记录里找回是谁批准的。对不上的，停在第 3 句的「否」，或者停在第 4 句的「承担不起」。

半自主仍然是 Agent。旋钮拧低，下一步还是模型选的，只是花钱、删除、对外发送之前要有人点头。Workflow 的下一步在设计时已经写死。第 11 章先把「停下来问」做成一次可以点的审批，第 15 章再把它写成档位并加上沙箱。

## 1.3.3 三个需求走一遍

拿三个需求，把四句走一遍。

**计算个人所得税。** 第 1 句的答案是「是」。税率表是公开规则，写成函数，结果可以用测试核对。问到这里就停。

**每收到一封邮件，就按固定类别归档并打标签。** 类别如果是一份写得完的清单——发票、行程、投诉、其他——第 1 句可能已经够用。还要跨邮箱和表格、按同一条路径搬运，第 2 句成立，用 Workflow。模型可以在「抽出发件人和主题」那一步帮忙。类别会临时冒出来、一封邮件同时像好几件事、下一步取决于正文里没人预见的内容，才进入第 3 句，考虑 Agent。自动回信、自动退订、自动删除，第 4 句成立，先问人。

**安排周末的杭州行程。** 天气、车次、酒店和老人的腿脚，会在中途改变后面的计划。输入是一句口语，路径事先列不完。第 3 句成立，可以做成 Agent：查天气、查交通、起草行程。真正去付款、去改别人的日历，第 4 句成立，停下来问。起草可以自己做，花钱和对外发送要等人点头。

这三个例子就是本章小结里的验收：找三个你自己的需求，按这个顺序各走一遍，写出停在哪一句、为什么。
