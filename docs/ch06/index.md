## 它记得文件，记不住你

第 5 章结尾，Harnex 已经能按你们的规范写周报了。第二天早上你再打开它，接着说：

```text
你> 昨天那份周报，「进展」的口径再收一收，只算能指到具体文件的。
Harnex> 你说的那份周报我这边没有记录。要改的是哪个文件？
```

`weekly-report` 技能包还老老实实躺在 `skills/` 目录里，重启就重新加载一遍——**所以它知道周报该怎么写。可上一轮到底发生过什么，磁盘上一点痕迹都没有。**

丢的东西有两样。

一样是 **关掉就没了**：进程一退出，前面聊的全部作废。另一样更隐蔽——**开着也不记得**。第 3 章的主循环每转一轮，都从一份全新的 `messages` 开始；你问「那北京呢」，它不知道上一句说的是上海。

第 3 章把这两件事记了账，说留到后面解决。这一章来还。

第 5 章也欠着一笔。技能包按需加载，省的是「一次装太多」；可上下文真正吃紧，往往是在**用久了之后**——翻过的文件、跑过的命令、几十轮对话，在 `messages` 里越堆越高。**上一章管「什么该进来」，这一章管「什么该出去」。**

## 本章要做的事

**第一件，把「对话历史」升级成「会话日志」。**

这两样长得像，干的活完全不同。`messages` 是「这一轮发给模型的东西」，会被裁剪、被摘要、被改写；会话日志是「到底发生过什么」，只增不减、能按时间回放。**分清了才敢压缩——因为压缩动的是投影，记录一个字不改。**

**第二件，搭一套上下文工程。** 记住该记的（长期记忆），忘掉该忘的（压缩），事后查得到（回看）。Harnex 会从「每句话都是初次见面」，变成「越用越懂你」。

读完这一章，你要能做到四件事：

1. 说清会话日志和 `messages` 是什么关系，为什么前者才是真相源
2. 上下文爆了，能用预算表指出是哪一块在吃 token
3. 判断什么时候该压、压掉什么、用哪种压法，并说清为什么压缩不能动日志
4. 设计一条记忆：该带哪些字段，用户纠正时怎么处理

**前置**：第 3 章的主循环与 `messages`；第 4 章的 `ToolRegistry`；第 5 章的技能包加载器（6.2 的预算表要读它的输出，6.6 把记忆也做成一个技能包）。

> **关于第 7 章**：本章几处演示里 Harnex 会「调 `shell` 跑测试」。它现在还不会——`shell` 是第 7 章的主角。读到时把它当成接口约定即可，不影响本章的日志与记忆逻辑。
