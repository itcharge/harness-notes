## 它读得到文件，却不知道该读哪个

第 7 章结尾，Harnex 学会了跑命令。你顺手把一个陌生的仓库丢给它：

```text
你> 帮我看看这个项目的认证是怎么做的。
Harnex> 我读了 README，列了目录，一共 137 个 Python 文件。
       你能告诉我认证逻辑在哪个文件里吗？我可以打开它仔细读。
```

「你能告诉我它在哪个文件里吗」——这不是偷懒，是它 **真的不知道**。它手里只有两样东西：`fs_read` 读你指定的文件，`shell` 跑你指定的命令。两样都要求你先说「看哪里」，而你要它回答的，恰恰就是「该看哪里」。

这一章给它装上第三种能力：**自己去找。** 它不再只能读你递到手里的纸，而是能在几万行代码、几百份文档里，把该看的那一段翻出来、读完、带回来给你。

## 本章要做的事

**第一件，把「它怎么会不知道」分成三类。** 模型的知识停在训练那天、资料从没公开过、内容多到装不下——三个病因，同一个出口：**别指望它记住，让它在需要时去查。** 顺带说清幻觉的来路：模型没有「我不知道」这个开关。

**第二件，把「检索」拆成三个零件。** 切块、嵌入、相似度。几十行代码就能跑起来，不必先装一整套向量数据库。三个零件里只有切块由你决定，而它恰恰是最容易拖垮全局的那一环。

**第三件，从「朴素 RAG」走到「Agentic RAG」。** 前者每次都检索、检索一次就答；后者让模型自己决定 **要不要查、查什么、查几轮、够不够**。这个转变是本章的主线。最后用十道题把两种做法量一遍——不量，你只能得出「Agentic 更聪明」这种没法指导决策的结论。

读完这一章，你要能做到四件事：

1. 说清什么该微调、什么该检索，以及为什么搞错方向的代价很大
2. 手写一个能跑的最小向量检索，并说清切块为什么是它的地基
3. 说清混合检索与重排各补上了哪一块短板
4. 说清 Agentic RAG 与朴素 RAG 的本质区别，以及它为什么不是「更准的检索」

**前置**：第 3 章那个 agent 循环（8.4 之后，检索只是它能调的又一个工具）；第 4 章的 `ToolRegistry`、工具描述与 `fs_read`（`search_docs` 就是个普通工具，检索的终点仍是打开原文）；第 6 章 6.6 的 `recall()`——它用关键词做的事，本章用向量做扎实；第 7 章的 `shell` 与那份命令白名单（8.5 会讲清 `code_search` 为什么不挂在 `shell` 底下，而是单独做成工具）。

> **关于规模**：本章的向量索引就存一个 JSON 文件，查询时在内存里暴力算余弦。几千块以内，这比任何向量数据库都快、都简单。**别在只有三份文档的时候就去搭基础设施**——什么时候该换，8.2.6 给了两个信号。
