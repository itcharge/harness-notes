# 8.1 为什么 LLM 需要外挂知识

## 8.1.1 三种不知道

模型答不出来，原因不止一种，药方也不一样——先把三条分开。

**第一类：知识截止日期。** 模型的知识全部来自训练数据，而那份数据停在某个时间点。那之后发布的新版本、改过的接口、上线的政策，它一律不知道。你问它，它照样答得笃定，可那是 **曾经正确** 的答案——这比「不知道」更麻烦，因为看不出破绽。

**第二类：私有文档。** 你团队的服务分层、上周设计评审的结论、你记在笔记里的踩坑记录——这些从没出现在任何公开语料里。模型不是「忘了」，是 **从来没见过**。指望它知道，等于指望它训练时翻过你的电脑。

**第三类：来不及。** 资料就在磁盘上，模型也读得懂，可一份 300 页的手册塞不进上下文——等你想翻，窗口已经满了。就算硬塞进去，之后每一轮跟它无关的对话，你都在为这几万 token 重复付钱。6.2 那张预算表量过这件事：上下文是零和的，装进手册就装不进对话历史。

前两类是它 **不知道**，第三类是它 **来不及**——装得下的太少，要读的太多。但三条路的出口是同一个：**别指望模型记住，让它在需要时去查。**

## 8.1.2 幻觉从哪来

常听到的说法是「模型会编，所以不能信」。这话对，但没说清 **为什么**。

生成模型只做一件事：给定上文，续写最可能出现的那段文字。「回答问题」是它的一个特例——交出来的是 **最像答案的那段文字**，不是 **核对过的事实**。麻烦在于训练数据里这两样分不开：一句「默认超时 30 秒」，出自官方文档还是三年前的博客，长得一模一样，口气也一样笃定。模型因此只学到「这类问题该怎么答」，没学到「这类问题该去查哪里」。它答得流畅，也错得流畅。

关键在这里：**模型没有「我不知道」这个开关。** 要它承认不知道，得靠专门训练或专门提示；它的默认动作是「给出一个听起来靠谱的答案」。所以外挂知识的第一层作用不是「喂它更多信息」，而是 **换掉它答题的依据**——从「我记得」换成「资料上写着」。资料里没有，它才有理由说没有。

## 8.1.3 微调和检索各改什么

「那我把公司文档喂进去微调一下，不就记住了？」

这是最常见的误判。先看这张表：

| 你想改的是 | 该用什么 | 为什么 |
| --- | --- | --- |
| 模型 **知道什么**：事实、文档、会变的信息 | 检索 | 换一份索引就更新，不用碰模型 |
| 模型 **怎么做事**：语气、输出格式、领域术语、固定流程 | 微调 | 这是行为模式，不是可查的事实 |
| 两者都要 | 先微调行为，再叠检索 | 行为稳定了，知识才能按需换 |

一句话就能判：**微调是把东西写进模型的「肌肉记忆」，检索是给它一本随手可翻的手册。**

写进肌肉记忆的东西，改一次很贵。你想让模型用你们团队的口吻写提交信息——适合微调，因为这套口吻稳定、不常变。你想让它知道「上周定价改成了 199」——绝不能微调，否则每改一次价就得重训一次，而且新旧事实会在权重里打架，模型可能一会儿说 199、一会儿说 299。

**会变的东西，永远不进权重。**

## 8.1.4 资料少就不必检索

检索不是无条件更好。Anthropic 在那篇讲 Contextual Retrieval 的文章里画了一条很实在的线：**知识库小于 20 万 token（约 500 页）时，整份塞进上下文更简单，配上提示缓存，成本和延迟都还能接受。**

这和 6.6.5 的「记忆少于 20 条，全量注入就够」是同一条规律的两个尺码：**工程上的第一原则，是别为不存在的规模付代价。** 检索有三笔账要付——灌入时要切块和嵌入，查询时要做一轮相似度计算，还多出一个新的失败模式「该召回却没召回」。这三笔账，只有规模真上来之后才被收益盖过。

所以本章的顺序是：先看清什么时候根本不用检索，再学需要时怎么做。

## 8.1.5 整份资料直接放进消息

写检索之前，先把「最简 RAG」写出来——它一行检索逻辑都没有：

```python
# harnex/retrieval/full_context.py —— 最简形态：不检索，整份资料塞进消息
# client 是 OpenAI SDK 的客户端（第 2 章那个）。它的 chat 够用，但没有 embeddings 接口——
# 8.2 要算向量时得换一个带嵌入的客户端，见 embed() 的注释。
def answer(client, question: str, docs: str) -> str:
    system = (
        "只根据下面的资料回答问题。资料里没有提到的，直接说资料中没有，"
        "不要凭常识补充。\n\n"
        f"===== 资料开始 =====\n{docs}\n===== 资料结束 ====="
    )
    resp = client.chat.completions.create(
        model="deepseek-flash",
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": question},
        ],
    )
    return resp.choices[0].message.content
```

这份代码里藏着 RAG 最容易被忽略、也最关键的一句：**「资料里没有提到的，直接说没有」。** 少了这句，模型会把资料当参考，再拿自己的记忆补全——你花力气喂了资料，它还是照训练数据答。

它缺的只有一步：**`docs` 大到装不下时，该挑哪一段放进去？**

那就是检索。下一节把这一步做出来：切块、嵌入、按相似度挑前几块。RAG 的其余部分——重排、混合检索、Agentic 循环——都是在把这一步做得更准。
