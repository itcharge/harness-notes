## 从上一章那段「没有循环」的代码说起

第 2 章结尾，你写出了一段能调用工具的代码。它能查一次杭州的天气，然后就停了。停在三个地方：

- 查完天气，自己再去查时间，或者再查另一座城市
- 看见返回结果之后，再决定下一步
- 这一问结束以后，在同一次运行里接着问下一句

第 2 章把那次调用说成「点一次菜」：模型写下要调用哪个函数，你的代码执行并把结果送回去，这一问就结束了。下一轮还没有写出来。结果回到模型手里之后，它还要再决定：继续调用工具，还是给出回答。

第 2 章的最后一句是：

> 本章那段没有循环的代码，下一章给它装上「心跳」。

这里的心跳，就是这个循环。跳一下，是做一步、看结果；接着跳，是直到模型给出回答，或者步数到了上限。这一章不用框架，把它写成大约 75 行。真正转起来的 `run()` 只有十来行，其余是两个工具，和一份给模型看的工具清单。3.2 的标题按「七十行」来记，把空行和命令行数进去是 75 行。

读完这一章，你要能做到四件事：

1. 说清 ReAct 留下的骨架：想一步、做一步、看结果、再想。以及它和今天 `tool_calls` 写法差在哪里
2. 亲手写出这个循环，并知道每一段在真实 harness 里叫什么
3. 说出循环里的五个问题，并指出这一章哪一个还空着（权限）
4. 得到 `harnex.py`：同一次运行里可以接着提问，一次任务里也可以调用两个工具。**Harnex 的代码从这里写出来**

命令行能接着问下一句，下一句仍看不到上一句。每轮 `run()` 都从空的 `messages` 开始。跨轮记忆是第 6 章的事。

> 这一章是后面各章的对照底稿。工具、记忆、审批和评测加进来以后，都可以指回这 75 行里的某一段。先看懂那段代码在回答哪个问题，再去记框架里的新名词。
