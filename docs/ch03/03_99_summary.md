# 小结与验收

## 本章小结

1. **循环 = 想 → 做 → 看 → 再想。** 它源自 ReAct 论文，现在实现只是不必再让模型打印 `Thought:`，整个骨架没变。
2. **大约 75 行里先回答四个问题**：做到哪一步（`messages`）、谁去执行（`TOOLS`）、怎样正常停（没有 `tool_calls`）、转个不停怎么办（`MAX_STEPS`）。做之前问不问人，这一章先空着。
3. **三行关键代码**：`MAX_STEPS`、结果先写成字符串、先记下模型的调用再记下工具结果。删掉 `messages.append(msg)`，工具结果会对不上一次调用。
4. **权限策略分三处补上**：第 4 章写明每个工具能干什么，第 11 章在会改文件、会花钱的动作前先问，第 15 章写成规则并加上沙箱。
5. **能能连着对话 ≠ 有记忆** 每一句都重新调用 `run()`，都从空的 `messages` 里开始追加。留到下一句，以及关掉程序之后还在，都是第 6 章的事。

## 动手任务

1. **敲一遍并发出去**：不要复制粘贴，手敲这 75 行。转圈的那十来行，对照 3.1 的五个问题，各写一句「这段在回答哪个问题」。
2. **做两个破坏性实验**：① 注释掉 `messages.append(msg)`，观察报错信息；② 把 `MAX_STEPS` 改成 1，问一个需要两步的问题，看它怎么被强制拦住。把两次的现象都记下来。
3. **加第三个工具**：给 Harnex 加一个 `search_wiki`（同样收 `args` 字典，从 `args["keyword"]` 取关键词，返回一段模拟文本即可），并写一条清晰的 `description`。然后问一个同时需要它和天气的问题，看模型会不会同时点名两个工具。

## 验收：一个回答「现在几点 + 上海天气」的 Demo

验收不看「代码能跑」，看 **它在几种典型问法下的行为是否符合预期**。用下面这张表逐条测：

| # | 测试问题          | 期望行为                              | 考察点           |
| - | ------------- | --------------------------------- | ------------- |
| 1 | 现在几点？         | 调 `get_time` 一次，直接回答              | 单工具、单轮        |
| 2 | 上海今天天气怎么样？    | 调 `get_weather` 一次，`city` 填对      | 带参数的调用        |
| 3 | 现在几点，顺便说说上海天气 | 调 `get_time` + `get_weather`，一次答全 | 一个回合里并行调用多个工具 |
| 4 | 北京和上海哪个热？     | `get_weather` 调两次，比较后回答           | 多步循环、结果对比     |
| 5 | 现在适合去上海吗？     | 先查时间、再查天气，综合给建议                   | 自主规划步骤        |

跑第 3 题时，注意观察：模型可能**在一个回合里同时点名两个工具**，也可能分两轮依次调用。两种都对——**这正是「自主决定下一步做什么」的体现**。你无法预先规定它走哪条路，只能给它工具、给它上限、看它怎么走。


第 5 题是最好的验收题。它没有标准答案，也没有标准步骤——**如果 Harnex 能自己判断「先查时间、再查天气、然后综合」，你就真的做出 Agent 了。**

## 本章的常见误区

- **没有圈数上限**：模型可能反复查同一个工具，一次提问变成十几次调用。`MAX_STEPS` 先把圈数写死。
- **工具结果没写回去，或写错位置**：`tool_call_id` 对不上会报错；`content` 忘了 `str()`，模型读不懂结果。
- **再要求模型打印 `Thought:`**：本章的决定看 `tool_calls`。在已经返回这个字段的调用上，再解析一段 `Thought:` / `Action:` 文字，只是多花 token。
- **把循环写成递归**：圈数一多就爆栈，而且无法在中间插入「先问人」（第 11 章）。
- **以为能接着输入就是记得住**：每一句都是一份新的 `messages`。留到下一句是第 6 章的事。
- **工具一危险就仍然不问**：本章两个工具只返回写好的话。能改文件、能跑命令之前，先补上「要不要问人」。

## 本章术语速查（中英对照）

| 中文    | 英文                           | 一句话解释                                       |
| ----- | ---------------------------- | ------------------------------------------- |
| 循环    | Agent Loop                   | 想 → 做 → 看 → 再想，直到完成                         |
| 推理与行动 | ReAct                        | Thought / Action / Observation 三段式（2022 论文） |
| 想法    | Thought                      | 模型决定下一步做什么（现代实现里已隐式化）                       |
| 观察    | Observation                  | 工具返回的结果，回填给模型                               |
| 状态载体  | State / Messages             | 循环中不断增长的消息列表                                |
| 执行器   | Executor                     | 真正执行工具的那段代码                                 |
| 终止条件  | Termination                  | 循环何时正常结束                                    |
| 熔断    | Step Limit / Circuit Breaker | 失控时的硬性上限                                    |
| 会话日志  | Session Log                  | `messages` 的工程化形态（第 6 章）                    |
