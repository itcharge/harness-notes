## 会做，但不懂章法

第 4 章结尾，Harnex 已经能读写你的文件了。你随手试一句：

> 把本周的工作整理成周报。

它跑得挺像样：调 `fs_read` 翻了翻 `notes/` 目录，然后写给你一段本周总结——

```text
本周完成登录模块优化、修复若干问题、推进其他事项，下周继续。
```

功能上没错。但你们团队的周报有规范：只分「进展 / 风险 / 待办」三类，进展必须能指出依据，风险必须带对策。Harnex 一条都没做到，**因为它不知道有这回事**。

这就是本章要补的那一层。上一章我们把「动作」做成了可插拔的——工具加进来就能用，搬进 MCP server 也能用。可**「方法」还是散的**：它躺在 wiki 里、躺在某个同事的脑子里、躺在你每次复制粘贴的那段 prompt 里。

> **工具让 Agent 能做一件事，技能包让 Agent 知道一件事该怎么做。**

**Agent Skills** 就是干这件事的格式：一个目录，一个 `SKILL.md`，把方法论写成 Agent 按需加载的知识包。它由 Anthropic 在 2025 年 10 月发布，同年 12 月成为开放标准（agentskills.io），不到一年接入的客户端就超过 70 个——Claude Code、ChatGPT、Codex CLI、Cursor、Gemini CLI、VS Code、GitHub Copilot 都在里面。

这一章给 Harnex 装上这层能力，然后你会看到它和工具层是 **同一套架构** 的两次应用：**知识可插拔，动作也可插拔。**

读完这一章，你要能做到四件事：

1. 说清工具、技能包、system prompt、检索这四层各自管什么，拿到一个需求能判断该放哪层
2. 读懂并写出规范的 `SKILL.md`，知道哪些内容该进 `scripts/`、哪些该进 `references/`
3. 给 Harnex 写一个技能包加载器，让它在启动时只花几百 token 就备好一整个技能库
4. 装一个陌生人的技能包之前，知道该按什么顺序审它

**前置**：第 4 章（工具注册表与权限声明）；会读写 YAML 的键值对（就这一个要求）。

> **关于第 7 章**：5.5 节讲技能包里的 `scripts/`，需要「能执行命令」这个能力。第 7 章才写 `shell` 工具——读 5.5 时把它当作接口约定记住即可，不必提前实现。
